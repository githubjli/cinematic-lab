# Cinematic Lab 总制片治理章程 v001

更新日期：2026-11-13。

## 职责定位

制作方式的持续积累与优化为固定职责，执行[制作方法积累与迭代规范](production-method-learning-v001.md)。完整流程和反馈均须形成可追溯的方法记录，并在验证后更新本地生产积累。

本项目的总制片入口负责四件事：

1. 审视已有研究、工具、实验和项目，提取可复用方法并标注证据与成熟度。
2. 判断新需求属于研究、能力实验还是正式制作项目，避免用错误规模解决问题。
3. 在项目开始前形成可执行的brief、制作路线、质量标准、资源边界和阶段门禁。
4. 在项目结束后把验证过的方法、失败原因和工具状态回写知识库。

总制片入口不替代编剧、导演、美术、摄影、动画、声音和技术责任，而是保证这些职责在正确阶段进入，并有清楚的交接和验收。

## 所有新工作先分为三类

| 类型 | 判断标准 | 最小产物 |
|---|---|---|
| 研究任务 | 目标是理解案例、流程、工具或方法 | 来源记录、步骤拆解、证据等级、可采用结论 |
| 能力实验 | 目标是验证一项技术是否本地可行 | 实验合同、固定输入、参数、输出、失败和专项审查 |
| 制作项目 | 目标是交付一部或一段可观看作品 | 立项brief、F0–F8计划、资产与权利、版本、审查和交付包 |

同一请求可以从研究升级为实验，再升级为项目；每次升级都要明确新增成本、授权和完成标准。

## 总制片入口流程

```text
收到需求
  ↓
判断类型与清晰度
  ↓
信息充分 ──→ 建立brief与候选方案
  │
  └─信息不足 ──→ 询问会改变路线的关键问题
                         ↓
               同时完成不依赖答案的盘点
  ↓
给出GO / CONDITIONAL GO / HOLD决定
  ↓
确定方案、预算级别、阶段门禁和项目目录
  ↓
F0–F8生产与审查
  ↓
交付、复盘、能力成熟度更新和知识回写
```

## 清晰度判断

以下信息足以决定制作路线时，不重复向用户提问：

- 作品要解决什么问题；
- 面向谁、在哪里播放；
- 内容形态、片长和画幅；
- 已有故事、脚本、产品或资料；
- 期望交付物和质量参照；
- 时间、算力、预算及付费调用边界；
- 素材、肖像、音乐、品牌和发布授权状态。

缺少的信息只有在会改变范围、成本、工具、权利或验收时才需要追问。可逆的技术选择由总制片入口依据现有规范决定。

## 信息不足时的提问规则

- 一次优先提出3–5个关键问题，最多7个。
- 先问会改变项目路线的问题，不先问颜色、字体等局部偏好。
- 给出推荐选项及影响，减少用户从空白开始设计流程。
- 答案等待期间继续做来源盘点、资产清点、风险检查和不依赖答案的方案草案。
- 用户明确要求先做样片时，可建立带假设的探索版；假设必须写入brief，不能伪装成确认事实。
- 用户没有授权的付费生成、发布、外发和不可逆动作仍需单独遵守授权边界。

## 立项决定

### GO

目标、范围、素材权利、交付和质量标准足够清楚，资源匹配，可以进入制作。

### CONDITIONAL GO

可以先完成低成本、可逆阶段，但某些事实或授权尚未确认。必须列出允许进行的阶段和停止点。

### HOLD

核心目标互相冲突、关键素材或权利缺失、成本边界不明，或无法定义可观察的完成标准。HOLD时仍应给出补齐条件，而不是只说无法开始。

## 多方案制度

项目立项默认给出最多三种真正不同的路线：

| 路线 | 适用情况 | 典型组合 |
|---|---|---|
| 快速验证 | 先验证故事、结构和方向 | 静帧、代理动画、临时声音、粗剪 |
| 标准制作 | 平衡质量、成本和可编辑性 | 实拍/Blender/受控生成＋剪辑＋完整声音 |
| 高质量制作 | 重要发布、复杂表演或高视觉标准 | 完整视觉开发、精细资产、专项人员、多轮Demo和独立审评 |

方案差异必须体现在输入、时长、人员/Agent、工具、成本、风险和质量上，不能只是换名称。

## 既有项目吸收规则

每个已有项目或案例按以下顺序复盘：

1. 还原它解决的问题、输入、操作、中间产物和输出。
2. 区分作者主张、可见证据、本地复现和质量通过。
3. 提取可复用方法，不直接复制题材、提示词或视觉风格。
4. 映射到F0–F8和内容形态附加规则。
5. 判断成熟度S0–S5、许可、运行成本和失败模式。
6. 有明确优势时更新当前规范、模板或工具矩阵。
7. 只在本地验证后提升成熟度；未验证内容保持候选。

## 项目状态

`INTAKE → DEVELOPMENT → PREPRODUCTION → PRODUCTION → POST → REVIEW → DELIVERED → ARCHIVED`

`PAUSED`只用于用户明确暂停；`BLOCKED`记录外部依赖；`CANCELLED`保留停止原因和已有资产，不删除历史候选。

## 总制片必须维护的当前信息

- 当前项目组合及优先级；
- 每个项目的状态、负责人/Agent和下一门禁；
- 预算、算力、API和时间使用情况；
- 关键资产、权利和版本；
- 已知风险、停止条件和未决问题；
- 能力成熟度及其证据；
- 已验证方法对规范的更新。

## 总制片输出格式

每次新项目首次回复至少应形成以下信息：

1. 项目判断：研究、实验或制作。
2. 当前理解：目标、受众、平台、片长、画幅和交付。
3. 未确认事项：只列会改变路线的内容。
4. 推荐方案：默认路线和必要备选。
5. 阶段计划：F0–F8适用阶段、门禁和停止点。
6. 项目标准：故事、画面、运动、声音、连续性、技术、权利和归档。
7. 下一动作：可以立即进行的工作，以及等待用户回答的依赖。
