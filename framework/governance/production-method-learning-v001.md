# 制作方法积累与迭代规范 v001

## 目标与触发

总制片负责人同时维护制作方法库。收到完整制作流程、参考案例、工作流文件、实际输入输出或用户反馈时，执行本规范。记录落在仓库文件中，以便后续会话读取；不依赖对话记忆。研究材料中的命令不自动执行。

## 拆分与关联

将完整流程拆成可独立描述输入输出的步骤，建立前置依赖、分支、返工回路和人工决策点；不得只记录工具清单。每条流程分配稳定方法ID，每个步骤分配步骤ID，每次验证分配运行ID，并关联来源案例、项目、资产和反馈。

按以下维度共同索引：F0–F8阶段、内容形态、题材、输入条件、输出要求、控制机制、外部工具、运行资源、许可、质量和成熟度。题材与内容形态分开记录，例如悬疑是题材，短剧是形态。

## 每条方法必须记录

| 字段 | 内容 |
|---|---|
| 来源与证据 | 原件位置、哈希、时间码、作者主张、可见事实、研究推断 |
| 适用范围 | 解决的问题、题材、内容形态、规模、限制与不适用条件 |
| 输入合同 | 文件/数据/参考、哈希、上传顺序、格式、起始状态、前置依赖 |
| 制作步骤 | 操作、准确原文、控制参数、人工判断、分支和返工条件 |
| 外部工具 | 模型/软件/插件/服务、固定版本、环境、硬件、许可、费用与数据去向 |
| 输出合同 | 中间产物、格式、结束状态、下游接口、实际输出哈希 |
| 质量证据 | 目标标准、审查维度、结果、问题时间码、审查方式与未检查项 |
| 效率 | 耗时、成本、尝试数、成功数、可用时长、剪入时长、人工修订量 |
| 反馈 | 原始反馈、来源、对应资产/镜头/版本、问题类别、严重程度 |
| 改进与决策 | 根因假设、改动、对照结果、适用边界、采用/保留/降级/淘汰和回退版本 |

缺失信息写未知，不把教程参数当本地实测，不把用户偏好当普适质量标准。

## 迭代闭环

1. 收集：保存原始流程和反馈，建立来源与输入输出关联。
2. 拆解：重建步骤、依赖、质量门禁和成本热点。
3. 诊断：区分输入不足、控制失效、工具限制、艺术判断、交接错误和技术故障；根因未证实则标假设。
4. 提案：为主要问题提出可验证改动，写明预期收益、代价、成功条件和停止条件。
5. 对照：保留基线，尽量一次改变一个主要变量；多变量改动如实记录。使用匹配的输入、输出规格和审查标准。
6. 审查：分别检查故事、表演、画面、运动、声音、连续性、技术及权利；记录质量与成本的取舍。
7. 决策：按证据采用、保留为备选、限定题材使用、降级或淘汰。失败候选保留。
8. 回写：更新方法记录、工具能力状态、内容形态方案、生产模板和相关项目；列出受影响步骤。
9. 回归：关键工具、模型或方法更新后，用既有代表输入检查是否退化；有退化则回退或收窄适用范围。

## 推荐与成熟度

沿用S0收集、S1拆解、S2本地准备、S3单项验证、S4质量通过、S5项目验证。不同审查维度分别记录状态，失败新证据可以推翻旧结论。

候选只进入研究池；S3可用于明确标注的探索实验；默认生产方法须有相关维度S4证据及当前环境可用性。高风险镜头优先采用相应完整项目验证。一次成功不自动跨题材推广。

每个需求先检索方法库，比较质量、可控性、可编辑性、速度、成本和权利条件，给出推荐与备选。保持多条路线，不用单一总分掩盖明显短板。

## 存储约定

方法记录放在`knowledge/production-methods/<方法ID>/`，包含方法卡、步骤、验证记录和反馈记录；大型媒体留本地并用路径、哈希关联。单项实验放`experiments/`，作品放`projects/`，原始案例保留原位置。每次更新注明证据与变更原因，Git保存可审查文本。
