# 镜头生产与后期交接模板包 v001

来源：案例031的组织方法与Cinematic Lab既有输入审计规范。适用于电影、短剧及多镜头叙事；按项目规模裁剪字段。复制到项目planning目录后填写，未知写unknown，非适用写not_applicable。

## 文件与使用顺序

1. `scenes.csv`：场次目标、信息和结束状态。
2. `assets.csv`：角色、状态、场景、道具、声音的版本与来源。
3. `shots.csv`：镜头任务、摄影、可见动作、情绪、声音和起止状态。
4. `references.csv`：按运行ID绑定实际输入文件、顺序和参考职责。
5. `dialogue.csv`：台词、角色、声线和关联镜头。
6. `runs.csv`：实际工具、原文文件、参数文件、成本和输出。
7. `reviews.csv`：分维度结果、时间码、缺陷和返工。
8. `handoff.csv`：选片与外部后期使用建议。
9. `change-requests.csv`：粗剪反馈、补镜和关闭证据。

镜头/运行/候选分别编号，例如S01_SH010、RUN-001、S01_SH010_C001。资产使用独立ID和状态ID；不以文件名相似代替身份关联。一个生成片段可以关联多镜头，镜号不强制等于一次调用。

## 核心规则

- 输入与输出均保存SHA256；顺序填实际提交顺序。
- 提交原文和参数保存为独立UTF-8文本/JSON，用路径与哈希引用，避免在CSV截断长文本。
- reference_role说明锁定什么；conflict_priority说明参考发生冲突时的处理意图，未知时先解决冲突。
- review_status区分not_reviewed、pass、conditional、fail；severity使用BLOCK、FIX、NOTE。
- 入出点为源素材秒数，必须满足0≤in<out≤实际时长；时间基准另存帧率，不能按播放器标签猜测。
- 交接帧记录来源候选与时间码，不默认必须取物理最后一帧；先审查再传递。
- 原始候选、处理版本与选用版本分别保留；上游换版后检查下游依赖。
- external_project_path和export_path由后期回填；外部工程未知时不宣称闭环完成。

## 最小交付检查

选片有源文件、哈希、可用区间、声音关联、起止状态、缺陷和授权状态；后期能定位文件；补镜任务有明确验收条件。成片技术、完整视听和权利验收仍按F7–F8执行。
