# Cinematic Lab 项目重新规划 v001

更新日期：2026-11-13。

## 一 项目现状判断

Cinematic Lab 已经从“分析参考视频中的AI制作方法”扩展为三个同时存在的系统：

1. **研究资料库**：30个参考视频、来源哈希、案例拆解和外部开源项目。
2. **电影制作知识库**：统一分析方法、流程技巧、工具选型、声音、MG、数学、机械、分镜和质量门禁。
3. **可复现制作实验室**：金耐力宣传片项目中的分镜、Blender、ComfyUI、声音、剪辑、审查和版本记录。

这三者都应保留，但必须明确层级。当前主要问题不是资料过多，而是入口、分类和成熟度没有统一表达。

## 二 当前结构的主要问题

### 分类维度混在一起

“电影、短剧、短视频、MG”是内容形态；“分镜、生成、剪辑、声音”是制作阶段；“Blender、ComfyUI、FFmpeg”是工具；“案例001–030、金耐力”是证据或项目。它们不应处于同一级目录或同一张总表中竞争。

### 文档按时间追加而不是按用途收敛

`tool-selection-addendum-v002`至`v011`、`workflow-techniques-v001`至`v010`保存了历史，但用户难以判断哪份是当前入口。历史版本应保留，另设“当前规范”汇总层。

### 研究结论与验证结果距离过近

视频中提到、作者声称、本地下载、成功运行、形成输出、通过视觉审查是不同状态。目前虽然各文档经常说明边界，但还缺一张跨项目成熟度矩阵。

### README定位已经过期

README仍写“原创故事和生成不属于当前授权工作”，但仓库已包含明确授权的制作试验。正确表述应是：研究、实验和具体项目分别按各自授权边界运行。

### 只有一个生产案例承担了过多验证任务

金耐力同时验证网页素材、产品片、机械动画、AI生成、声音、竖屏和审评。它适合作为工业产品片基准，但不能代表剧情电影、短剧、知识片和MG的全部需求。

## 三 新的项目定位

> Cinematic Lab 是一个面向AI辅助影视生产的研究、方法和验证仓库。它把参考案例转化为可追溯的方法规范，通过小型实验验证关键技术，再用完整项目验证端到端制作流程。

项目交付分成三类：

| 交付类型 | 解决的问题 | 完成标志 |
|---|---|---|
| 方法规范 | 一部作品应如何从开发走到交付 | 有输入输出、角色分工、质量门禁和记录字段 |
| 能力实验 | 某项技术是否在本地可行 | 有固定输入、实际参数、输出、失败记录和专项审查 |
| 参考项目 | 多项能力能否组成可观看作品 | 有完整制作档案、连续音画审查和明确发布状态 |

## 四 稳定的分类架构

### 第一轴 制作阶段

这是全项目的主轴，所有内容形态共用：

| 编号 | 阶段 | 核心输出 |
|---|---|---|
| F0 | 项目开发与制片 | brief、受众、预算、片长、发行、权利边界 |
| F1 | 故事与剧本 | 故事结构、人物、场次卡、锁定剧本 |
| F2 | 视觉与声音开发 | 风格圣经、色彩脚本、声音概念、参考证据 |
| F3 | 资产与一致性 | 角色、场景、道具、声音资产及状态版本 |
| F4 | 导演分镜与预演 | 镜头任务、分镜、动态预演、场面调度、交接状态 |
| F5 | 镜头制作 | 实拍、三维、生成、视效和候选版本 |
| F6 | 后期 | 选片、剪辑、合成、调色、对白、拟音、音乐和混音 |
| F7 | 质量与合规 | 故事、表演、连续性、运动、声音、技术和权利审查 |
| F8 | 交付与归档 | 母版、派生版、字幕、分轨、项目文件、哈希和恢复验证 |

### 第二轴 内容形态

内容形态只定义对主流程的不同要求，不复制一套完整流程：

| 内容形态 | 特殊重点 |
|---|---|
| 长片与电影 | 长程人物弧光、跨场连续性、大规模资产和长期后期 |
| 短剧与漫剧 | 分集钩子、批量产能、角色一致性和模板化资产 |
| 短视频与广告 | 开场注意力、单一主张、竖屏安全区、快速变体和平台交付 |
| 产品与品牌片 | 产品真实性、卖点证据、品牌规范、实拍/三维/生成混合 |
| 知识与科普片 | 事实、因果、图表、数学与解释层的准确性 |
| MG与代码视频 | 时间线、排版、数据、运动曲线、节拍和图形质量 |
| 音乐与MV | 音乐结构、节拍、表演、视听同步和音乐权利 |

### 第三轴 实现机制

工具按能力挂接到制作阶段，不用工具名称定义流程：实拍、二维图形、三维、生成模型、代码时间线、声音工作站、Agent编排和资产管理。

### 第四轴 证据与成熟度

| 状态 | 含义 |
|---|---|
| S0 收集 | 只有链接、视频或作者主张 |
| S1 拆解 | 已形成输入输出和步骤分析 |
| S2 本地准备 | 已下载代码、资产或运行环境 |
| S3 单项验证 | 已用固定输入运行并保存结果 |
| S4 质量通过 | 已完成相应视觉、运动、声音或技术审查 |
| S5 项目验证 | 已在完整作品中使用并通过跨镜头审查 |

成熟度必须按能力分别标记，不能给整个工具或整个项目一个笼统的“已验证”。

## 六 需要建立的六个当前入口

1. **电影生产总流程**：F0–F8的输入、输出、责任角色和门禁。
2. **内容形态选择器**：根据长片、短剧、广告、知识片、MG选择附加规则。
3. **能力与工具矩阵**：任务、运行条件、许可、成熟度和替代方案。
4. **统一数据规范**：场次、镜头、资产、提示词、候选、审查和交付字段。
5. **案例证据地图**：每条方法由哪些案例支持，证据达到什么等级。
6. **验证路线图**：下一项实验为什么做、补哪个证据缺口、什么算通过。

## 七 案例与实验重新分工

### 参考案例

案例001–030继续作为方法证据，不再直接承担“推荐工具”或“当前流程”的入口职责。

### 金耐力项目

定位为“工业产品竖屏宣传片参考项目”，主要验证产品素材授权、机械三维、物料一致性、受控生成、声音、剪辑和独立审评。

### 后续建议增加的最小基准项目

| 基准 | 建议规模 | 主要验证 |
|---|---|---|
| 剧情短场景 | 30–60秒、两人一场 | 剧本、表演、角色一致性、对白、正反打和接戏 |
| 知识解释片 | 45–90秒 | 事实核验、图表/数学、旁白、MG和声音层次 |
| 短剧小集 | 60–120秒 | 分集钩子、资产复用、批量镜头和Agent交接 |

不应同时启动三个完整制作。先用最小场景补齐当前最弱的“人物表演与对白连续性”。

## 八 执行原则

- 新研究先回答它补充F0–F8中的哪个缺口，否则只进入候选池。
- 新工具先进入能力矩阵，不直接进入默认工作流。
- 新案例必须有来源、证据等级和可复用结论，不只写摘要。
- 新实验必须有固定输入、成功条件、失败条件和停止条件。
- 当前规范采用单一文件入口；旧版本保留但不继续层层追加。
- 完整项目必须同时管理故事、画面、运动、声音、连续性、技术和权利状态。
- 文件存在、代码运行和视频可播放只代表技术事实，不代表作品质量通过。

## 九 重新规划的阶段顺序

### 阶段A 建立导航

更新README，建立总流程、内容形态、能力矩阵、案例证据和成熟度五类入口。停止继续创建无汇总关系的addendum文档。

### 阶段B 收敛规范

把已有统一方法、技巧索引、导演手册、质量门禁和工具表提炼成F0–F8当前规范。旧文件作为来源链接。

### 阶段C 建立数据模板

统一场次卡、镜头表、资产清单、生成记录、审查报告和交付清单，并在金耐力项目回填验证。

### 阶段D 建立验证矩阵

列出每项能力的S0–S5状态、证据和缺口，避免重复研究已解决的问题。

### 阶段E 补齐人物电影能力

选择一个30–60秒剧情短场景，重点验证人物、表演、对白、接戏和声音，不追求长片规模。

## 十 当前决策

本轮只建立新总纲和路线图，不移动、不重命名、不删除历史文件。下一步应优先完成F0–F8电影生产总流程和统一数据模板，再决定目录迁移。
