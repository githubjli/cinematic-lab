# 本地音效库与生成工作台方案 v001

更新日期：2026-10-14。此方案承接案例019。案例020–022不是声音工具案例。当前只形成技术方案，未安装模型、未下载权重、未调用付费服务、未生成音频。

## 是否能本地实现

可以。建议把“音效库”拆成六个独立能力：原件入库、技术元数据、语义描述/向量检索、波形试听与裁切、重复候选、缺口生成。前五项可完全本地运行；生成也可本地运行，但显存、速度、音质和模型权重许可决定是否适用。

`只读原件 → SHA256/音频指纹 → FFmpeg探测与预览 → SQLite元数据 → CLAP向量 → 本地检索/试听/裁切 → 生成候选 → 人工听审 → 导出`

## 推荐最小实现

| 层 | 本地组件 | 产物 | 边界 |
|---|---|---|---|
| 存储 | 文件系统＋只读原件目录 | 原始音频、编辑副本 | 不覆盖原件；素材许可单独记录 |
| 数据库 | SQLite FTS5 | 描述、标签、来源、许可、镜头用途、审查状态 | 先做文本检索即可起步 |
| 技术处理 | FFmpeg/FFprobe | 时长、采样率、声道、响度、波形代理、裁切 | 不判断语义和审美 |
| 完全去重 | SHA256 | 完全重复组 | 不能找重新编码或不同裁切 |
| 近似去重 | Chromaprint等音频指纹＋人工复核 | 相似候选组 | 不自动删除；设计相似声可能都要保留 |
| 语义检索 | Microsoft CLAP或LAION CLAP | 音频/文字向量、相似度 | 需实测中文查询，可增加中英标签 |
| 界面 | FastAPI＋本地网页/Gradio | 搜索、试听、标记、导出 | 首版不必做复杂无限画布 |

Microsoft CLAP官方仓库提供音频/文本嵌入、相似度计算和音频描述能力，代码为MIT；权重来源和具体使用条件仍需逐项记录。它适合“找声音”，不负责生成新波形。

## 本地生成候选

| 候选 | 能力 | 运行与许可判断 | 建议 |
|---|---|---|---|
| AudioCraft AudioGen | 文本生成环境声/音效 | 官方文档称medium约1.5B，推理建议至少16GB GPU；代码MIT，公开权重为CC-BY-NC 4.0 | 研究和非商业原型候选；商用不要默认可用 |
| AudioLDM | 文本到音频、音频到音频、风格迁移、补绘路线 | 可本地CLI/Gradio；检查点许可与代码许可分开核对，常见公开权重含非商业限制 | 适合做多候选和音频引导实验 |
| 现场拟音/程序合成 | 录音、噪声、振荡器、滤波与包络 | 完全可控，权利链较清楚 | 脚步、触碰、界面音、简单机械声优先考虑 |

生成接口必须接收结构化事件：声源、动作、材质、空间、距离、强度、时长、演化、排除项、种子和候选数。输出进入`candidates/`，状态默认为`unreviewed`，不能直接进入成片。

## 数据结构

每条资产至少保存：`asset_id`、原件哈希、编辑父项、来源URL/作者/许可、文件格式、采样率、声道、时长、中文描述、英文描述、标签、CLAP模型与向量版本、生成提示/模型/种子、使用镜头、听审状态。向量必须可重建，数据库备份不替代原件备份。

## 实施顺序

1. 先做FFmpeg＋SQLite＋本地网页，实现入库、标签、搜索、试听、裁切和哈希。
2. 加音频指纹与“重复候选”页面，任何删除都由人工决定。
3. 加CLAP语义检索，用一组中文查询评估召回；必要时同时保存英文规范描述。
4. 再接一个本地生成器，只生成音效库缺口，保留全部候选与准确参数。
5. 用声音事件表连接剪辑时间线，完成单条听审、声画同步和整片混音三级验收。

这一路线在普通CPU机器上也能完成基础音效库；只有向量批处理和生成阶段明显受GPU影响。硬件信息当前未知，因此不承诺实时速度或可运行的模型档位。
