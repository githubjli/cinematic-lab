# Toonflow短剧流程与角色功能划分 v001

整理日期：2026-10-13。分析对象为用户提供的文章及Toonflow官方仓库快照`ae9e5f1ac4f37713b902fed7fa5ca87819b324ae`。文章中的安装提示只作材料，未执行安装、构建、模型配置或媒体生成。官方仓库：[HBAI-Ltd/Toonflow-app](https://github.com/HBAI-Ltd/Toonflow-app)，官网：[toonflow.net](https://toonflow.net)。

## 结论

Toonflow的核心价值不是“六个Agent自动拍完一集”，而是把剧本、资产、分镜、生成节点和结果放在同一画布中，使每一步的输入输出可见并可局部返工。最适合把它理解为短剧生产工作台与执行编排层；图像、视频、语言和语音能力来自所配置的模型或本地工作流，质量、费用和限制随供应商变化。

文章中的六个岗位可以作为职责清单，但不是当前版本已确认的固定运行架构。当前快照的`workflow`技能明确称其“不依赖原来的多岗位Skill组”；仓库仍支持团队机制，可验证的`storyboardTeam`示例由导演、分镜编写、分镜审阅三名成员组成。角色数量应服从交付边界，不应为“六个”而六个。

## 推荐生产流程

| 阶段 | 主要动作 | 必须保存的产物 | 人工关口 |
|---|---|---|---|
| 0. 立项与范围 | 确认改编范围、集长、画幅、平台、风格、预算和模型能力 | 原文快照、制作简报、未知项、预算上限 | 范围确认 |
| 1. 剧本 | 将创意/小说改为可视听剧本，保留事件、台词、动作与声音 | 剧本版本、原文映射、修改记录 | 剧本锁定 |
| 2. 资产规范 | 提取角色、场景、道具；建立身份、服装、材质及状态 | 角色档案、三视图/多角度、场景和道具表、资产哈希 | 资产批准 |
| 3. 导演规划/预演 | 分场、节奏、空间轴线、表演重点；必要时用3D导演台摆位与调焦 | 导演方案、机位/焦距、空间图、预演截图或方案 | 镜头策略确认 |
| 4. 分镜 | 把场次拆成可生成的镜头或片段，注明景别、构图、动作、运镜、声音和时长 | 分镜表、镜头ID、参考映射、连续性起止状态 | 分镜批准 |
| 5. 图像资产与分镜图 | 生成或导入角色/场景/道具/构图参考，逐项筛选 | 所有候选、采用记录、参考文件哈希 | 参考图通过 |
| 6. 视频镜头生成 | 每镜连接真实参考，设置模型、模式、时长、画幅等参数 | 完整提交原文、上传顺序、参数、任务ID、费用、全部结果 | 单镜采用/退回 |
| 7. 质检与返工 | 检查剧情、身份、服装、道具、空间、动作、闪烁、口型和声音 | 时间码问题单、严重度、责任阶段、修订版本 | 镜头锁定 |
| 8. 剪辑与交付 | 镜头组接、配音、音乐/音效、字幕、响度、编码与横竖版适配 | 时间线、音轨、字幕、版权记录、导出参数、成片哈希 | 最终验收 |

官方README当前给出的产品主路径是四步：剧本与分镜→角色/场景参考→视频镜头→预览、整理与下载。它证明了前述工作台主干，但没有单凭README证明“一键完成最终剪辑、混音和双画幅重构”；这些应作为独立交付阶段验证。

## 角色职责与边界

| 角色 | 负责 | 交付物 | 不应负责 |
|---|---|---|---|
| 制片人/人类负责人 | 范围、预算、授权、版本采用和最终决策 | 简报、预算表、批准记录、采用清单 | 把批准权默认交给Agent |
| 导演/编排 | 把锁定剧本变成场次、节奏、表演和镜头策略；协调返工顺序 | 导演方案、空间轴线、镜头目标、关口决策 | 擅自改写锁定剧情；代替质检自我通过 |
| 编剧 | 原文改编、事件因果、对白与可视听动作 | 原文映射、剧本、变更说明 | 决定模型参数；把未确认补充写成原作事实 |
| 分镜 | 把导演方案转成可执行镜头 | 分镜表、镜头时长、构图/运镜、声音提示、连续性状态 | 承诺生成结果；用漂亮画面掩盖剧情遗漏 |
| 资产/一致性 | 管理人物身份、服装、道具、场景状态和跨镜头参考 | 资产库、角色板、状态表、每镜参考映射 | 宣称三视图可绝对消除漂移；规避平台审核 |
| 生成执行 | 按已批准镜头装配节点、参考和模型参数 | 实际输入、顺序、参数、任务/费用记录、所有候选 | 静默更换模型；把“已提交”写成“已通过” |
| 质检 | 独立检查剧情覆盖、可执行性、连续性、运动和声音 | 时间码问题单、严重度、最小修正建议、复检结果 | 只看静帧就通过运动/声音；直接替用户批准 |
| 配音/声音 | 声线表、对白时序、语气、环境声/动作声及音轨交付 | 声音圣经、台词表、音频文件与授权、响度记录 | 改写台词而不回剧本；把音频生成等同混音完成 |
| 剪辑/交付 | 镜头取舍、节奏、字幕、混音、横竖版重构、最终编码 | 时间线、工程/EDL、字幕、母版与发布版 | 用自动裁切代替逐镜构图检查 |

小团队可以由同一个人或Agent兼任多个角色，但批准人与产出者最好分开；最低限度保留“制作执行”和“独立质检”两个不同检查视角。

## 3D导演台与一致性模块怎样接入

当前源码中存在`director3dNode`：可用低多边形关节人偶、基础几何体搭建场景，调整摄影机位置、视线和焦距，并保存摄像机关键帧进行镜头预演。它适合验证站位、轴线、景别和运动路径，是预演工具，不是最终画质或视频模型效果证明。

角色三视图/多角度资产用于定义身份和造型；视频生成时再把角色、场景、道具和必要的分镜图映射到具体参考槽位。三视图不应被当成视频首帧，也不应整张拼图无差别喂给每个镜头。应记录每镜实际使用的参考、顺序和权重，并以结果审查决定是否采用。

## 技术与运营边界

- 官方说明服务默认使用固定端口3000，页面和API没有独立登录鉴权；远程部署应限制来源或使用带认证的反向代理。
- 软件采用MIT许可，但第三方模型、插件、素材、字体、声音和输出内容各自核对许可及费用。
- 当前快照的工作流包含强绑定特定模型路线的规则，说明“自由接模型”不等于每套上层工作流自动兼容所有模型；应按实际供应商能力验证参考数、时长、分辨率和音频。
- 文章中的安装/配模型文字没有被执行。准备部署方案也不等于授权安装、录入API Key或付费生成。

## 建议试点

先做20–30秒、一个场景、两名角色、4–6个镜头的竖屏片段。用同一锁定剧本比较三组：仅单张角色图、完整角色资产、角色资产加3D预演分镜。固定模型和参数，记录费用与失败率，比较身份、服装、空间、动作连续性以及返工时间。只有小样通过后再评估两分钟整集。
