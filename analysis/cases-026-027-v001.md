## 两条视频最值得借鉴的共同点

两者表面分别是AI音乐MV和摄像头开花小游戏，核心却相同：先把连续媒体变成稳定的控制信号，再让视觉系统消费这些信号。

## 案例026：节拍先于画面

### 视频可见流程

1. 以热门MV为参考，观察其音乐风格、歌词、文字运动和构图。
2. 把可见的Suno风格描述交给AI分析，再写新的音乐生成要求；视频也显示Suno可接受音频参考，但没有展示完整提交原文和参数。
3. 用AI分析歌词/歌曲应如何运镜，把镜头写成带秒数的动作说明。
4. 从音频抽取节拍，保存为`beats.json`；视频画面显示全曲得到约210个节拍节点。
5. 让代码动画读取节拍、人声和歌词时间，生成文字、波形、图形和转场；再比较两个模型标签下的实现。
6. 人工评价结果：模型能完成同步和基本动效，但复杂度、变化控制与审美仍取决于提示细度、参考和人工判断。

### 借鉴价值

- **先生成控制数据**：`beats.json`比“跟着音乐动起来”更可检验。每个节拍有绝对秒数，镜头、文字和音效可以定位和局部重渲染。
- **强弱拍分级**：不应让每个节拍都触发大动作。按小节首拍、段落边界、歌词重音和静默分为A/B/C级事件，分别控制切镜、构图变化和微动。
- **参考拆成属性**：参考MV只提供节奏密度、留白、字体尺度、色彩和运动语法；新作品另写歌词、画面与设计，避免把复刻当原创。
- **提示词分层**：先给全片规则，再给段落目标，最后给镜头时间、主体、动作、起止状态、缓动和禁项。视频中的“保持当前风格，后面别重复”过于模糊，容易得到重复或无计划变化。
- **模型比较用同一测试包**：固定音频哈希、节拍表、歌词时间、画幅和验收帧，再比较代码正确性、同步误差、视觉层级和修改成本。成片“看起来更丰富”不能单独证明模型更强。

### 推荐输入输出契约

```text
输入：audio.wav + beats.json + lyrics.json + storyboard.json + design-tokens.json
中间：可编辑源码 + 指定时刻静帧 + 每段5–10秒预览 + 渲染日志
输出：final.mp4 + 分轨音频 + 所有输入/输出哈希 + 人工审查记录
```

实现候选可用Remotion、Canvas/WebGL、After Effects表达式或Blender；本项目已有Remotion选型记录。视频没有露出实际渲染框架，因此不能据此认定其使用Remotion，也不能把视频所示模型标签、功能和质量视为独立验证。

## 案例027：把关键点变成语义控制

### 视频可见流程

视频展示一个“BLOOM”花朵页面：摄像头区域叠加手部骨架，页面根据手指张开程度改变花朵开放比例，摆手切换Lotus、Lily、Rose、Camellia、Cherry等花种。21个关键点是可见说明，具体库、阈值、代码和授权未展示；结尾提到源码/教程获取，也不等于已确认公开仓库或开源许可。

### 可复用实现链

`摄像头 → 手部检测/跟踪 → 归一化特征 → 平滑 → 手势状态机 → 动画参数 → UI反馈`

- **关键点归一化**：以掌宽或腕到中指掌指关节距离作为尺度，避免手靠近镜头时阈值失效。
- **张开度映射**：用指尖到掌心的归一化距离、手指夹角或各指伸展状态汇总，映射到`bloomProgress` 0–1；花瓣只读取这个参数。
- **切换与连续控制分开**：张开度是连续值；左右摆手是离散事件。离散手势需冷却时间，不能每帧切换。
- **去抖与滞回**：滑动平均或One Euro Filter降低抖动；进入和退出阈值分开，防止花在临界点反复开合。
- **状态机**：至少包含`NO_HAND / TRACKING / BLOOMING / SWITCH_COOLDOWN`，检测丢失时平滑停留或回到安全状态。
- **即时反馈**：保留关键点覆盖、识别置信度、开放百分比和当前花种，便于用户理解动作是否被识别，也便于调试。
- **性能验收**：记录检测FPS、端到端延迟、丢帧率、误触发率及不同光照/肤色/左右手/遮挡测试。静态截图不能证明这些指标。

Google MediaPipe的官方手部方案确实使用手掌检测与手部关键点模型，并返回每只手21个关键点；其Web任务源码和示例可作为开源实现候选。是否就是视频所用方案仍为未知。

## 适用场景

| 技巧 | 合适场景 | 不宜直接套用 |
|---|---|---|
| 音频→事件时间线 | 音乐MV、歌词动画、预告片、节奏剪辑、数据可视化 | 依赖表演连续性的写实叙事，不应机械逢拍切镜 |
| 关键点→状态机 | 展览互动、网页小游戏、科普装置、无接触控制、舞台视觉 | 安全关键控制、精细手语理解，需专门数据与严格验证 |
| AI写代码/动效 | 快速做候选、重复模板、参数化版本 | 将首次生成直接当成最终审美和稳定软件 |

## 本项目落地建议

优先做两个最小验证件：一段15秒节拍驱动文字动画，以及一个仅含“张开控制开花、左右挥手切换”的本地网页。两者都先保存控制JSON、源码和预览，不调用付费生成。通过同步、稳定性和交互审查后，再决定是否扩成完整MV或互动片头。
